# Symfony Automations
`serversideup/php` has a "Symfony Automations" script that helps you automate certain steps during your deployments. By default, the script is **DISABLED**. We only recommend enabling this script in production environments.

::note
`AUTORUN_ENABLED` must be set to `true` to enable the script. The script automatically detects Symfony by checking for the presence of both the `bin/console` file and `symfony.lock` file in your application directory. The `symfony.lock` file is created by Symfony Flex and ensures the automations only run for Symfony projects. See our [variable reference document](/docs/reference/environment-variable-specification) for more details.
::

## What the script does
This script executes on container start up and performs the following tasks:

### Doctrine Migrations
Before running migrations, we ensure the database is online and ready to accept connections. By default, we will wait 30 seconds before timing out.

The migration behavior can be controlled with `AUTORUN_SYMFONY_MIGRATION_MODE`:

#### Default mode (normal migrations)
```bash
AUTORUN_SYMFONY_MIGRATION_MODE=default
```
Runs `php bin/console doctrine:migrations:migrate --no-interaction --allow-no-migration`

This is the **recommended mode for production deployments** as it safely applies new migrations without data loss.

#### Schema reset mode
```bash
AUTORUN_SYMFONY_MIGRATION_MODE=schema-reset
```
Runs:
1. `php bin/console doctrine:schema:drop --force --full-database`
2. `php bin/console doctrine:schema:create`

**Use this mode with caution** - it will drop and recreate your schema. Useful for development environments or when you want to sync your database with your entity definitions without migrations.

#### Fresh mode
```bash
AUTORUN_SYMFONY_MIGRATION_MODE=fresh
```
Runs:
1. `php bin/console doctrine:database:drop --force --if-exists`
2. `php bin/console doctrine:database:create`
3. `php bin/console doctrine:migrations:migrate --no-interaction --allow-no-migration`

**Use this mode with caution** - it will completely drop and recreate your database. Ideal for staging environments or when you want a clean slate with all migrations applied.

### Multi-Database Support
You can run migrations on multiple database connections by specifying a comma-separated list:

```bash
AUTORUN_SYMFONY_MIGRATION_DATABASE=default,tenant,analytics
```

The script will:
1. Wait for each database connection to be ready
2. Create each database if it doesn't exist (when `AUTORUN_SYMFONY_DATABASE_CREATE=true`)
3. Run the selected migration mode on each connection sequentially

This is useful for applications with tenant databases or separate analytics databases.

### Database Auto-Creation
By default, the script will automatically create databases that don't exist:

```bash
AUTORUN_SYMFONY_DATABASE_CREATE=true  # default
```

This runs `php bin/console doctrine:database:create --if-not-exists` before migrations, ensuring databases exist before attempting to migrate them.

### Fixtures Loading
Load fixtures into your database by setting `AUTORUN_SYMFONY_FIXTURES=true`. You can choose between two fixture providers:

#### Doctrine Fixtures (Default)
Uses [doctrine/doctrine-fixtures-bundle](https://symfony.com/bundles/DoctrineFixturesBundle/current/index.html) for loading fixtures.

```bash
AUTORUN_SYMFONY_FIXTURES=true
AUTORUN_SYMFONY_FIXTURES_PROVIDER=doctrine  # default
```

By default, this will purge and reload all fixtures. If you want to append fixtures instead of purging, set:

```bash
AUTORUN_SYMFONY_FIXTURES_APPEND=true
```

Runs `php bin/console doctrine:fixtures:load --no-interaction`

#### Zenstruck Foundry (Modern Alternative)
Uses [zenstruck/foundry](https://github.com/zenstruck/foundry) for loading fixtures with stories and factories. Available since Foundry 2.6+.

```bash
AUTORUN_SYMFONY_FIXTURES=true
AUTORUN_SYMFONY_FIXTURES_PROVIDER=foundry
```

Runs `php bin/console foundry:load-fixtures --no-interaction`

**Benefits of Foundry:**
- Modern, expressive API for creating test data
- Uses stories and factories for better organization
- Type-safe fixture generation
- Better suited for local development fixtures

**Note:**
- If Foundry is not installed and you select it, the script will automatically fall back to Doctrine fixtures with a warning
- The `AUTORUN_SYMFONY_FIXTURES_APPEND` option only works with Doctrine fixtures
- Fixtures are typically used in development and testing environments. Only enable in production if you specifically need seeded data

[Read more about Foundry →](https://symfony.com/bundles/ZenstruckFoundryBundle/current/index.html#loading-fixtures)

### Cache Warmup
This command warms up the Symfony cache for optimal performance. **Enabled by default** when automations are active.

```bash
AUTORUN_SYMFONY_CACHE_WARMUP=true  # default
```

Runs `php bin/console cache:warmup`

This is a **production best practice** that pre-generates cache files for better initial response times.

[Read more about cache warmup →](https://symfony.com/doc/current/configuration.html#clearing-and-warming-up-the-cache)

### Assets Install
Install web assets to the public directory. **Disabled by default.**

```bash
AUTORUN_SYMFONY_ASSETS_INSTALL=true
```

Runs `php bin/console assets:install --no-interaction`

Enable this in production if you're serving assets directly through Symfony instead of through a build process.

### Doctrine Schema Validation
Validate that your database schema matches your Doctrine entity mappings. **Disabled by default.**

```bash
AUTORUN_SYMFONY_SCHEMA_VALIDATE=true
```

Runs `php bin/console doctrine:schema:validate`

This is useful in **development environments** to catch mapping issues early. Not typically run in production as schema validation failures are non-fatal.

### Messenger Transport Setup
Setup Messenger transports (queues/topics) for async message handling. **Disabled by default.**

```bash
AUTORUN_SYMFONY_MESSENGER_SETUP_TRANSPORTS=true
```

Runs `php bin/console messenger:setup-transports --no-interaction`

Enable this in production if you're using Symfony Messenger with transports that need initialization (like Doctrine, Redis, or AMQP).

[Read more about Messenger →](https://symfony.com/doc/current/messenger.html)

## Utility Scripts

### Console Command Wrapper
A convenience wrapper script `console` is available to run Symfony console commands from anywhere:

```bash
# Instead of: php /var/www/html/bin/console cache:clear
console cache:clear

# Works with any console command
console debug:router
console messenger:consume async
```

The wrapper automatically resolves the correct path based on `APP_BASE_DIR` (defaults to `/var/www/html`).

### Healthcheck Scripts
Built-in healthcheck scripts for monitoring long-running Symfony processes:

#### Messenger Workers
```yaml
healthcheck:
  test: ["CMD", "healthcheck-messenger"]
  interval: 30s
  timeout: 3s
  retries: 3
```

Checks for running `messenger:consume` processes.

#### Scheduler Workers
```yaml
healthcheck:
  test: ["CMD", "healthcheck-scheduler"]
  interval: 30s
  timeout: 3s
  retries: 3
```

Checks for running `messenger:consume scheduler_*` or `scheduler:consume` processes (Symfony 6.3+ Scheduler component).

## Production Best Practices

### Recommended Configuration for Production
```yaml
environment:
  - AUTORUN_ENABLED=true
  - AUTORUN_SYMFONY_MIGRATION=true
  - AUTORUN_SYMFONY_MIGRATION_MODE=default
  - AUTORUN_SYMFONY_CACHE_WARMUP=true
  - AUTORUN_SYMFONY_ASSETS_INSTALL=false  # Use build process instead
  - AUTORUN_SYMFONY_FIXTURES=false  # Never in production
  - AUTORUN_SYMFONY_SCHEMA_VALIDATE=false
  - AUTORUN_SYMFONY_MESSENGER_SETUP_TRANSPORTS=true  # If using Messenger
```

### Recommended Configuration for Development/Staging
```yaml
environment:
  - AUTORUN_ENABLED=true
  - AUTORUN_SYMFONY_MIGRATION=true
  - AUTORUN_SYMFONY_MIGRATION_MODE=fresh  # or schema-reset
  - AUTORUN_SYMFONY_CACHE_WARMUP=false  # Not needed in dev
  - AUTORUN_SYMFONY_FIXTURES=true
  - AUTORUN_SYMFONY_FIXTURES_PROVIDER=foundry  # or doctrine (default)
  - AUTORUN_SYMFONY_SCHEMA_VALIDATE=true
```

## Environment Variables Reference

| Variable | Default | Description |
|----------|---------|-------------|
| `AUTORUN_ENABLED` | `false` | Master switch to enable all automations |
| `AUTORUN_DEBUG` | `false` | Enable debug logging for troubleshooting |
| `AUTORUN_SYMFONY_MIGRATION` | `true` | Enable Doctrine migrations |
| `AUTORUN_SYMFONY_MIGRATION_MODE` | `default` | Migration mode: `default`, `schema-reset`, or `fresh` |
| `AUTORUN_SYMFONY_MIGRATION_DATABASE` | _(empty)_ | Comma-separated list of database connections (e.g., `default,tenant`) |
| `AUTORUN_SYMFONY_MIGRATION_TIMEOUT` | `30` | Database connection timeout in seconds |
| `AUTORUN_SYMFONY_MIGRATION_SKIP_DB_CHECK` | `false` | Skip database connection check (use with caution) |
| `AUTORUN_SYMFONY_DATABASE_CREATE` | `true` | Automatically create database if it doesn't exist |
| `AUTORUN_SYMFONY_FIXTURES` | `false` | Load fixtures |
| `AUTORUN_SYMFONY_FIXTURES_PROVIDER` | `doctrine` | Fixture provider: `doctrine` or `foundry` |
| `AUTORUN_SYMFONY_FIXTURES_APPEND` | `false` | Append fixtures instead of purging (Doctrine only) |
| `AUTORUN_SYMFONY_CACHE_CLEAR` | `true` | Clear cache before migrations |
| `AUTORUN_SYMFONY_CACHE_WARMUP` | `true` | Warm up Symfony cache |
| `AUTORUN_SYMFONY_ASSETS_INSTALL` | `false` | Install web assets |
| `AUTORUN_SYMFONY_SCHEMA_VALIDATE` | `false` | Validate Doctrine schema |
| `AUTORUN_SYMFONY_MESSENGER_SETUP_TRANSPORTS` | `false` | Setup Messenger transports |

## Examples

### Example: Production Deployment with Migrations
```yaml
version: '3.8'
services:
  app:
    image: serversideup/php:8.3-fpm-nginx
    environment:
      AUTORUN_ENABLED: "true"
      AUTORUN_SYMFONY_MIGRATION: "true"
      AUTORUN_SYMFONY_CACHE_WARMUP: "true"
      APP_ENV: "prod"
    volumes:
      - ./:/var/www/html
```
